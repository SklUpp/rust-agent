## (D) Open decisions & risks

1. **TUI model:** alt-screen loses native scrollback; inline viewport is required for Termux UX. Choosing alt-screen makes `tui.resizeScrollback` dead config. This is the biggest product-visible drift.
2. **R9 root naming:** `~/.aragent` vs XDG `aragent`; dual-read plus old lock-root compatibility. If lock roots move while old sessions are open, must avoid two writers. Copy-only means disk duplication and confusing stale `~/.omp`; doctor needs a migration report, not silent copy.
3. **Android XDG:** current `init-xdg` creates unused directories on Android; resolver excludes Android. Fix gate or document Android as unsupported. Termux `$HOME`/`$PREFIX` symlinks complicate canonical roots.
4. **R10 semantics:** unknown outcome must survive process restart and be visible in next session; confirmation must be shared across TUI/headless/RPC/ACP and must never be satisfiable by `yolo` or a hook. No auto-retry invariant is stronger than UI convenience.
5. **PathMap authority:** physical path must remain authority; reverse ACP client may see a different root. Unmapped write/terminal paths leak host paths and can write to the wrong client workspace. Symlink swap between resolve and open is a TOCTOU risk.
6. **Doctor destructive actions:** `--redact-legacy` rewrites history; backup is atomic but user must supply a safe path; multiple DBs require a backup directory. `--prune-artifacts` can delete blobs shared across session DBs, hence `--session-dir` is rejected. Never add auto-fix for these.
7. **Hooks trust:** project hooks are gated by `trust.json` fingerprint, but hooks are not sandboxed and receive full tool payloads; a trusted hook can exfiltrate secrets. Keep fail-closed and consider stdin redaction/allowlist before exposing to less-trusted projects.
8. **Docs/status drift:** R11 and hooks are implemented but marked pending; doctor probe list differs; `plan.defaultOnStartup` and exit codes are documented beyond code. Update plan/decisions before using them as acceptance truth.
